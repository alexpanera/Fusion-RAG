# Fusion-RAG

## Overview
Local-first RAG pipeline for textbook PDFs. No cloud APIs, no LangChain, no external vector DBs.
Everything runs on the machine using Ollama (local LLM) + FAISS (dense vectors) + BM25 (sparse).
Stack: Python 3.10+, sentence-transformers, faiss-cpu, rank-bm25, PyMuPDF, pdfplumber, requests.

## Key Commands
- `python -m ragbook ingest --pdf data/book.pdf --out data/index` — Ingest PDF and build index
- `python -m ragbook ingest --pdf a.pdf b.pdf --out data/index` — Ingest multiple PDFs
- `python -m ragbook ask --index data/index --q "What is plasma confinement?"` — Ask a question
- `python -m ragbook ask --index data/index --q "..." --retrieval_only` — Debug: show chunks only
- `python -m ragbook eval --index data/index --eval data/eval.jsonl --out results.csv` — Batch eval

## Coding Standards
- Type hints on all functions following existing style: `str | None`, `list[dict]`, `list[str]`
- Use `LOGGER` from `ragbook/utils.py` — never `print()` inside library code
- No new dependencies — the 7 packages in `requirements.txt` are sufficient
- No hardcoded values — use environment variables for anything runtime-configurable
- No breaking changes to CLI flags (`--index`, `--q`, `--top_k`, `--pdf`, `--out`, etc.)

## Architecture

```
ragbook/
├── __main__.py     # CLI entry point: ingest / ask / eval subcommands
├── __init__.py     # Version metadata
├── ingest.py       # PDF text extraction (PyMuPDF → pdfplumber fallback) + header/footer removal
├── chunking.py     # Section-aware chunking with overlap; heading detection heuristics
├── embeddings.py   # EmbeddingModel (sentence-transformers) + SQLite EmbeddingCache
├── index.py        # build_and_persist_index / load_index; FAISS + BM25 + metadata
├── retrieve.py     # hybrid_retrieve: normalize dense+sparse scores, fuse, return top-k
├── llm_ollama.py   # OllamaClient: HTTP calls to /api/generate, model auto-selection
├── prompt.py       # build_answer_prompt: context budget, text cleaning, citation format
├── eval.py         # run_eval: JSONL → CSV with retrieval_hit and answer_hit metrics
└── utils.py        # LOGGER, estimate_tokens, tokenize_for_bm25, citation, make_chunk_id

data/
├── *.pdf           # Source PDFs
└── index/          # Index artifacts (generated by ingest)
    ├── chunks.jsonl       # All chunks with metadata
    ├── faiss.index        # Dense vector index
    ├── bm25_tokens.pkl    # Tokenized corpus for BM25
    ├── emb_cache.db       # Embedding cache (SQLite)
    └── meta.json          # Index metadata (model, chunk count, source PDFs)
```

## Important Patterns

### 1. Logging (not print!)
```python
# CORRECT
from ragbook.utils import LOGGER
LOGGER.info("Retrieved %d chunks for query: %r", len(results), query)

# WRONG
print(f"Retrieved: {results}")
```

### 2. Environment variables for config
```python
# CORRECT — already the pattern used throughout
import os
top_k = int(os.getenv("RAG_TOP_K", "6"))

# WRONG
top_k = 6  # hardcoded
```

### 3. Hybrid retrieval weights
Dense and sparse scores are each normalized to [0,1] then combined:
```python
hybrid = dense_weight * dense_norm + sparse_weight * sparse_norm  # retrieve.py
```
Default: 65% dense / 35% sparse. Tunable via `--dense_weight` / `--sparse_weight` CLI flags.

### 4. Heading detection is heuristic
`chunking.py` uses two detectors — ALL CAPS lines and Title Case lines followed by body text.
When modifying chunking logic, test against real PDFs — these heuristics are sensitive to PDF formatting.

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `OLLAMA_HOST` | `http://localhost:11434` | Ollama server URL |
| `OLLAMA_MODEL` | auto-selected | Override which model to use |
| `OLLAMA_TIMEOUT_SEC` | `600` | Request timeout in seconds |
| `EMBED_MODEL` | `BAAI/bge-small-en-v1.5` | Embedding model (HuggingFace) |
| `RAG_TOP_K` | `2` | Default number of chunks to retrieve (tuned for 3000-char budget on CPU; raise with GPU) |
| `RAG_MAX_CONTEXT_CHARS` | `3000` | Max characters of context sent to LLM (tuned for qwen2.5:7b on CPU; raise to 8000+ with GPU) |

## Supported PDF Types

Only **text-based PDFs** work (selectable text). Scanned/image PDFs need OCR preprocessing first.
PDF extraction tries PyMuPDF first; if the result is sparse (<100 chars total), falls back to pdfplumber.

## Common Tasks

### Add a new PDF
```bash
# Re-ingest with the new file added to the list
python -m ragbook ingest --pdf data/existing.pdf data/new.pdf --out data/index
```

### Improve retrieval quality
1. Try adjusting weights: `--dense_weight 0.5 --sparse_weight 0.5`
2. Increase retrieved chunks: `--top_k 8`
3. Use a larger Ollama model: `--ollama_model qwen2.5:7b`
4. Debug what's being retrieved: `--retrieval_only`

### Run eval against a question set
```bash
# Create data/eval.jsonl with lines like:
# {"question": "What is a tokamak?", "expected_keywords": ["tokamak", "magnetic"]}
python -m ragbook eval --index data/index --eval data/eval.jsonl --out results.csv
```
